**What it does.** Each run card in "Driver payments" gets a **Pay with Everee** button for a super admin on a server where Everee is set up (the status endpoint says `configured`); everyone else sees nothing new. It is separate from "Mark as paid", which stays for money paid outside Everee, as Jasil asked.
- **Click 1** opens a dialog with the server's preview (`GET .../runs/:runId/everee-preview`): who would be paid and how much, who is left out and why, the total, whether this is the sandbox ("No real money moves") or live, and anything that blocks the whole batch (payments switched off, the person who finalized the run cannot confirm, a live city without settings). Nothing is sent.
- **Click 2** is "Confirm and pay N drivers, $X" (the count and total come from the server's preview). It sends the preview's hash and a request ID. The request ID stays the same until the preview changes, so a second click or a lost answer cannot send twice (the server replays it). If what would be paid changed, the server answers 409 with the new preview, which replaces the old one with a message; the next confirm uses a new request ID. After an unclear failure the screen reloads what the server has, because the batch may exist.
- **Results** (`GET .../runs/:runId/everee-batches`) show each driver in words: *Sent to Everee* (waiting for approval in the Everee portal and the deposit; **never shown as Paid**), *Paid* (only when Everee confirmed the deposit), *Not sent* (Everee refused; can be retried), *Unconfirmed* (check it in Everee), plus a "deposit returned by the bank" line. **Check now** and **Retry what failed** call the part 5 and part 4 endpoints. Nothing on this screen decides what is paid: it only shows the server's answers.
- Not stored anywhere in the browser. No new text for drivers; this is an admin screen in English like its neighbours.

**Tested.** Vitest with a fake server (7 tests): the button is offered only to a super admin where Everee is set up; the first click only shows the preview and sends nothing; the confirm button names the count and total; confirming sends the shown hash and a request ID and the result says sent and waiting, never paid; a lost answer then another click repeats the same request ID; a changed preview shows the new one, sends nothing and uses a new request ID next; the finalizer and a blocked batch cannot confirm and the reason is shown; every result status is shown in words and retry and check call the right endpoints. A new request ID on every click makes 1 test fail, not gating confirm on the server's answer makes 1 fail, and showing "sent" as "Paid" makes 2 fail (checked). The whole frontend suite passes (238), lint is clean and the build works. Jasil's `PaymentRuns` tests pass unchanged (the card is still rendered without a redux store there; the role is read safely when there is none).

A real payment reaching "Paid" still waits on the sandbox funding account and approving the payroll run in the Everee portal (see the part 5 entry).
