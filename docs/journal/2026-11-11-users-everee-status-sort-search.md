# Users page: Everee onboarding status, sorting and filters

With many drivers it was hard for admins to see who had finished Everee onboarding. The Drivers table on the Users page now has an **Everee** column with each driver's status in words (Onboarded, In progress, Not started, Needs review, Not needed for Desi, Type not set, Everee not set up), chips above the table with a count for each status that filter it when pressed, and a note for a Local driver who is not onboarded saying what is missing from NASA's own records (no valid 10-digit phone, agreement not signed, a one-word name: the three things Everee setup needs from NASA). A note says when Everee onboarding is switched off, and when not-onboarded Local drivers are on hold from work and pay (enforcement on). "Onboarded" is the state in which a Local driver is active for work and pay.

Filters: driver type, account (enabled or disabled) and "needs fixing" (no valid phone, agreement not signed, one-word name), next to the existing search (name, email, phone, driver code) and city. Sorting: press a column heading (Driver code, Name, City, Driver type, Everee, Account) to sort and again to reverse, or use the Sort by list and Order button (phones). Sorting by Everee status puts the drivers with work left first (needs review, not started, in progress), then onboarded, then not applicable. Every change starts again from the first page and clears the selection, so a driver you can no longer see is never changed by accident. Filters show as removable tags and Clear removes them all.

The status is worked out by the server from NASA's own records, the same way the payment setup overview does it (a live Everee link for the configured environment and tenant, with onboarding complete); nothing is asked of Everee and nothing is written. Ordinary admins see only their own cities, as before; super admins see all. The list is now one query (`Backend/services/admin/driverList.js`) that also returns the total and the per-status counts; the old list and count queries are unused by this page. Every choice (filter, sort, direction, page) is checked against fixed lists before it reaches the query. No migration.

Validation: a database test (rolled back, made-up drivers) for every status, counts, each filter, sorting both ways, search (a % or _ is just a character), pagination, who may see which drivers, Everee not configured, and that reading changes nothing; unit tests for the input checks; 13 page tests for the status column, chips, filters, sorting and banners; whole frontend (565) and backend suites pass. Not checked: with the real Everee data of production, where most Local drivers start as "Needs review" or "Not started" until they open the app.
