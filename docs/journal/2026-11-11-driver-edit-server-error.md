# Editing a driver: say what is wrong instead of "Server error"

An admin saving the Edit Driver form in production got a red "Server error" and nothing else. The server logs only the message, so the exact cause in production is not known from here, but the update path had several ordinary mistakes that all ended as a 500, each reproduced on the local database: an email another driver already has (the create form checks this, the edit did not; the table has a unique email), a phone number over 20 characters or an email over 150, a driver code that is not a whole number or is out of range, a city that is disabled (the lookup throws), and a form that leaves `enabled` or the driver code out (the columns cannot be empty).

Now: email, phone and driver code are checked before the database (`driverUpdateRules.js`); another driver's email is a 409 "Another driver already uses this email" (the database refusal is mapped the same way for a race, for the driver code too, and on the create form); a disabled or missing city is a 400 that says so; a missing `enabled` or driver code keeps the driver's current value. Anything else is still a 500, but the log now carries the database code and constraint, so the next real cause can be read from the log.

If the production error is none of these, the log line "Update user error" now shows its `code` and `constraint`.

Validation: unit tests for the rules, and a database test (`PAYROLL_TEST_DB=1`) that runs the real controller on two made-up drivers (removed afterwards): it fails on the old controller with a 500 and passes now. Whole backend suite passes (302).

**Phone number is now required (added to the same pull request).** Everee cannot onboard a driver without a valid phone, and the form said "optional", so drivers were added with none and could never finish payment setup; saving them again later was a likely source of the production error. The phone is now required in the Add and Edit driver form and on the server (create and edit): a US number of 10 digits, a leading 1 allowed, the same rule Everee's matching uses. Editing a driver who has no phone asks for one; nothing is guessed or filled in. Existing drivers without a phone are not changed: they get a clear message the next time an admin saves them, until a phone is entered. To list them: `SELECT id, name FROM drivers WHERE phone_number IS NULL OR btrim(phone_number) = '';`.
