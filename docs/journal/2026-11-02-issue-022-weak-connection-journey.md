**What and why.** Section 6 of `docs/MOBILE_APP_DESIGN.md`: the app must work on weak connections without losing what was typed and without lying about whether something was saved. Done for the driver's journey form, the daily write.
- **Drafts.** The route and sequence numbers a driver types are kept in `sessionStorage` (private to the tab or WebView, never shared), keyed by area and driver. They are restored after a reload or a WebView restart, removed when the journey is saved, and all of an area's drafts are removed at sign-out. A different driver signing in on the same phone sees an empty form. Only short plain-text values are kept.
- **Uncertain save.** Before, a failed request showed a "Network Error" message although the server might have saved the journey, and a second tap then ran into "already saved". Now a request that gets **no answer at all** (the connection dropped) is flagged by the slice; the page asks the server for today's journey and then shows one of three things: **saved** (the usual success, with the request sent only once), **"It was not saved. What you typed is still here. Please submit again."** (submit works again), or **"We could not confirm this was saved"** with Check again, while Save stays switched off so the same journey cannot be sent twice. It checks again by itself when the connection returns.
- **Reload while unconfirmed (review fix, 2 Nov 2026).** The first version kept the unconfirmed state only in React state while the typed entries were in `sessionStorage`, so reloading the page brought the entries back with Save switched on again, even though nothing had confirmed the first save (and if the lookup was still failing, the page treated that as "not saved"). Now an unconfirmed save is also remembered in `sessionStorage` (`formDrafts.markPending`, key `nasa.pending.<area>.<person>.<form>`, value = the submission's date), apart from the draft. After a reload the form is blocked from its very first render while that mark exists (it is read during render, not copied into state), the notice is shown, and the check is run again by itself; the mark is removed as soon as the server answers either way (saved, or not there), and kept while it cannot be reached. A mark for another day is dropped without being checked, another driver's mark is never seen (the person's id is part of the key), and sign-out removes every mark of the area with the drafts. No offline replay queue was added: nothing is resent by the page, the person still taps Save again themselves, and only after the server has been asked. If `sessionStorage` is blocked the mark only lives until the page is reloaded. A real refusal from the server (a 400 with a message) is unchanged.
- **Success is only shown after the server confirms.** A failed refresh of the journey list *after* a confirmed save used to turn the success into a failure message; it no longer does.
- **`Idempotency-Key` is not built, and is not needed for now.** Checked in the code: a second journey for the same driver and day is already refused (`journey.alreadySaved`, a 400 before the insert) and a second access code with the same code is already refused (`accessCode.alreadyExists`, a 409). A repeated request cannot create a duplicate, so the missing piece was the page's behaviour, not the backend. Recorded in the design document.

**Tested.**
- `npm test` in `Frontend/`: 95 of 95 on this branch (75 before the review, plus 20 across the branches below it and the review fix; the review fix itself adds 15, listed after this entry). 5 for the draft storage (per area, person and form; blanks are not stored; hostile or oversized stored values are cleaned; clearing one draft or one area touches nothing else; no error when storage is blocked). 10 with the real journey form, slices and sign-out and a fake server that can drop the connection: a normal save; a failed list refresh after a confirmed save; a drop after the server saved (shown as saved, request sent once); a drop before it saved (entries kept, second submit works, two requests in all); the server unreachable for the check (Save stays off, a click sends nothing, then it settles by itself on the `online` event); Check again by hand; a real 400 refusal is not treated as uncertain; restore after a reload and removal once saved; another driver sees an empty form; sign-out removes the drafts.
- Mutation checks: ignoring the flag, not blocking submit while unconfirmed, not clearing drafts at sign-out, and the slice not flagging each make tests fail.
- `eslint` clean on the files touched; `vite build` succeeds.
- **Not tested:** on a phone, or with a real weak connection (only a simulated drop, answered or not). The `online` event in the real WebViews. The look of the notice on a small screen.

**Not built, and why.** The same handling for the access-code and agreement forms (the access-code form is 736 lines with images that cannot be restored, and needs its own change), and the read-only cache with a freshness label, which depends on a decision of Jasil's about which screens may show old data. Both are described in the design document.

**Risks and follow-ups.** The check relies on "today's journey exists" meaning "this save worked", which is true because only one journey per driver and day is allowed. If that rule ever changes, the check must compare the saved values.
- Reload tests (review fix, 15 new: 8 with the real journey form, 4 for the hook, 3 for the storage helpers): after a reload with the server still out of reach the notice is back, the entries are restored, Save is off and a click sends nothing; Save is already off on the first render (hook test that records every render); with the server reachable after the reload it shows saved with no second request, or says it was not saved and a second submit works (two requests in all); the connection returning later settles it by itself; another driver on the same phone is not held up; sign-out forgets it; a mark from an earlier day neither blocks nor is checked. Mutation checks, all caught: no block before the first check, no resume after a reload, `begin` not remembering, an earlier day's mark not dropped, a settled check keeping the mark, and sign-out leaving the marks.
